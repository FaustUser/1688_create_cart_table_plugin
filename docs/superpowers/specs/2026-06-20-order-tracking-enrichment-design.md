# Добавление трек-номеров в Excel

## Цель

Добавить в popup расширения второй самостоятельный сценарий: пользователь загружает ранее созданный плагином Excel-файл, расширение получает трек-номера заказов на 1688 и скачивает новую копию файла со столбцом `Трек номер`.

Текущий сценарий формирования Excel сохраняется без изменения поведения.

## Интерфейс

Вместо одного общего блока popup показывает две карточки действий:

1. `Собрать новый файл` — открывает существующие настройки и запускает текущий экспорт.
2. `Добавить трек-номера` — предлагает выбрать `.xlsx` или `.xlsm` и запускает обогащение файла.

Во время обогащения вторая карточка показывает:

- общий процент выполнения;
- `Обработано X из Y заказов`;
- текущий номер заказа;
- количество заказов с найденными треками;
- количество заказов без треков;
- количество оставшихся заказов;
- кнопку `Остановить`.

После завершения карточка показывает итоговые счётчики и кнопку скачивания не требует: файл скачивается автоматически. При ошибке конкретного заказа процесс продолжает работу, а его ячейка остаётся пустой.

## Выполнение в фоне

Оркестрацией управляет service worker расширения, а не popup. Поэтому закрытие popup не останавливает обработку. Текущее состояние задания хранится в `chrome.storage.local`; после повторного открытия popup восстанавливает прогресс и подписывается на дальнейшие обновления.

Одновременно используется только одна фоновая вкладка 1688:

1. Из Excel извлекаются уникальные непустые номера заказов.
2. Для очередного заказа открывается неактивная вкладка:
   `https://air.1688.com/app/ctf-page/trade-order-detail/index.html?orderId=<ORDER_ID>&to=logisticsTabTitle`.
3. После загрузки content script ожидает появления данных доставки и извлекает все значения, связанные с `运单号码` или `Номер накладной`.
4. Значения нормализуются, дубли удаляются с сохранением порядка.
5. Вкладка закрывается и начинается следующий заказ.

Для одного заказа несколько трек-номеров объединяются символом перевода строки. Если трек не присвоен, страница не загрузилась или данные не удалось распознать за установленный таймаут, результат для заказа остаётся пустым.

Кнопка `Остановить` помечает задание отменённым, закрывает текущую служебную вкладку и не создаёт частичный итоговый файл. Повторный запуск начинает обработку заново.

## Извлечение данных со страницы

Парсер не зависит только от одного CSS-класса. Он обходит обычный DOM и открытые shadow root, ищет подписи `运单号码` и `Номер накладной`, затем проверяет:

- соседний элемент;
- ближайшую строку или контейнер пары «подпись — значение»;
- текст после разделителя `:` или `：`;
- атрибуты и текст элементов в ограниченном контейнере доставки.

Значение принимается только после удаления текста подписи и служебных пробелов. Одинаковые значения не повторяются.

Для уточнения разметки предусматривается диагностический режим: при ненайденном треке content script возвращает ограниченный фрагмент текста логистического блока в журнал расширения, но не записывает его в Excel.

## Изменение Excel

Поддерживается файл, созданный текущим экспортом плагина. Рабочий лист определяется по имени `Товары`; столбец заказа — по заголовку `Номер заказа`, а не по фиксированному индексу.

В лист вставляется новый столбец непосредственно после `Номер заказа`:

`Номер заказа` → `Трек номер` → `Картинка`.

Файл изменяется на уровне XLSX ZIP/XML, чтобы сохранить существующие картинки, стили и остальные данные:

- ссылки ячеек правее точки вставки сдвигаются на один столбец;
- обновляются диапазон листа, ширины колонок, формулы и автофильтр, если они присутствуют;
- anchors изображений в drawing XML сдвигаются на один столбец;
- новый заголовок получает стиль соседнего заголовка;
- ячейки треков получают перенос текста;
- строки с одинаковым номером заказа получают одинаковый набор треков.

Если столбец `Трек номер` уже существует, повторный запуск обновляет его без вставки ещё одного столбца.

Исходный файл не перезаписывается. Итог скачивается под именем вида `<исходное имя>_с_треками.xlsx`.

## Состояние задания

Состояние содержит:

- идентификатор задания;
- имя и байты исходного файла;
- список уникальных заказов;
- индекс текущего заказа;
- отображаемый текущий номер;
- отображение `номер заказа → трек-номера`;
- счётчики `found`, `empty`, `remaining`;
- статус `idle`, `running`, `cancelling`, `completed`, `failed`;
- идентификатор текущей служебной вкладки;
- текст общей ошибки, если итоговый файл создать невозможно.

Popup получает первоначальный снимок через сообщение и последующие изменения через `chrome.runtime.onMessage`.

## Ошибки и ограничения

- Файл без листа `Товары` или заголовка `Номер заказа` отклоняется до открытия вкладок.
- Пустой список заказов не запускает обработку.
- Ошибка одного заказа не завершает всё задание.
- Общая ошибка чтения или записи XLSX завершает задание со статусом `failed`.
- Служебная вкладка закрывается в `finally`, включая отмену и таймаут.
- Одновременно допускается только одно задание.
- Авторизация пользователя на 1688 используется из текущего профиля Chrome.

## Проверка

Автоматические тесты должны покрывать:

- поиск столбца заказа и вставку `Трек номер`;
- повторное обновление уже существующего столбца;
- сдвиг ячеек, формул, диапазонов и anchors изображений;
- заполнение всех строк одинакового заказа;
- объединение нескольких треков через перенос строки и удаление дублей;
- пустой результат при отсутствии данных;
- извлечение треков из нескольких вариантов DOM;
- переходы состояния фонового задания, отмену и продолжение после ошибки одного заказа;
- восстановление отображения прогресса после повторного открытия popup.

Ручная проверка выполняется на копии реального файла и нескольких заказах: с одним треком, несколькими треками и без присвоенного трека.

## Отклонённые варианты

- Прямые HTTP-запросы к внутреннему API 1688: быстрее, но сильнее зависят от токенов и закрытых контрактов.
- Поиск заказа в разделе `全部`: зависит от пагинации и состояния списка.
- Пересборка Excel с нуля: проще, но может потерять изображения, стили и неизвестные элементы исходного файла.
