# Построчное сопоставление товаров и трек-номеров

## Проблема

Текущая реализация возвращает для страницы заказа один список строк и записывает его во все строки Excel с этим номером заказа. Из-за этого:

- в трек попадают `发货时间` и дата отправки;
- при нескольких отправлениях все товары получают все треки заказа;
- невозможно определить, какой товар был отправлен конкретной накладной.

## Модель данных

Content script возвращает массив отправлений:

```js
[
  {
    trackingNumber: "435233621072490",
    products: [
      {
        offerId: "1020395271677",
        title: "9031【充电式280电机5档调速】入门配",
        normalizedTitle: "9031充电式280电机5档调速入门配"
      }
    ]
  }
]
```

Трек-номер извлекается только из значения рядом с подписью `运单号码` или `Номер накладной`. Значение принимается только если похоже на идентификатор перевозчика: одна строка без служебных подписей и даты. `发货时间`, даты и прочие поля никогда не попадают в `trackingNumber`.

## Границы отправления

Для каждой найденной подписи трек-номера парсер определяет минимальный родительский контейнер, который одновременно содержит:

- одну или несколько подписей/значений доставки;
- блоки товаров, ссылки на `detail.1688.com/offer/<id>.html`, изображения или наименования;
- не содержит другие независимые подписи `运单号码`.

Если DOM не даёт надёжной границы, используется ближайший повторяющийся sibling/card-контейнер. Парсер обходит обычный DOM и открытые shadow root.

## Извлечение товаров отправления

Внутри контейнера отправления собираются:

- `offerId` из ссылок `detail.1688.com/offer/<id>.html`;
- видимый title товара;
- SKU/вариант, если он отображается;
- количество, если доступно.

Название нормализуется: Unicode NFKC, нижний регистр, удаление пробелов, пунктуации и служебных подписей. Исходный title сохраняется для диагностики.

## Сопоставление со строками Excel

Для каждой строки листа `Товары` читаются:

- номер заказа;
- ссылка и `offerId`;
- `Название на 1688`;
- количество.

Приоритет:

1. точное совпадение `offerId`;
2. точное совпадение нормализованного title;
3. единственное включение одного нормализованного title в другой при достаточной длине;
4. однозначное совпадение по набору значимых токенов.

Если несколько строк или отправлений остаются равноправными, сопоставление не выполняется. Ячейка остаётся пустой, а диагностическая запись содержит номер заказа, строку Excel и кандидатов.

Если товар входит в несколько отправлений, его уникальные треки записываются через перенос строки.

## Хранение результата

Фоновое задание хранит:

```js
shipmentDataByOrder[orderNumber] = shipments;
```

При финальной сборке XLSX `tracking-xlsx.js` вычисляет треки отдельно для каждой строки, используя данные строки и отправлений. Старый `trackingByOrder` поддерживается только для обратной совместимости тестовых/старых состояний, но новый процесс его не создаёт.

## Прогресс и ошибки

Единицей прогресса остаётся заказ. Ошибка разбора одного заказа оставляет его строки пустыми и не прерывает обработку. Счётчик `found` означает заказы, где сопоставлена хотя бы одна товарная строка.

## Проверка

Тестовая DOM-фикстура содержит один заказ, два отправления и четыре товара. Проверяется:

- даты отправки не входят в трек;
- товары разных отправлений получают разные треки;
- несколько товаров одного отправления получают одинаковый трек;
- один товар в нескольких отправлениях получает несколько треков;
- `offerId` имеет приоритет над названием;
- неоднозначные совпадения остаются пустыми;
- фактические первые четыре строки файла `1688_parsed_Товары (3).xlsx` сопоставляются с ожидаемыми треками при подаче соответствующей структуры отправлений.
